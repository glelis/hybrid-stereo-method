Método Estéreo Híbrido — mapa completo do pipeline

Fluxo de execução e todos os parâmetros do projeto hybrid-stereo-method, extraídos diretamente do código-fonte em 2026-07-11 (branch bugfix/auditoria-2026-06-09). O método combina estéreo multifocal (profundidade a partir da variação de foco) com estéreo fotométrico (normais a partir da variação de iluminação) e integra as normais em um mapa de altura, usando a profundidade multifocal como "dica" (hints).

Etapa 1 · Multifocal Etapa 2 · Fotométrico Etapa 3 · Integração Etapa 4 · Avaliação arquivo / artefato parâmetro do YAML não consumido declarado no YAML mas ignorado pelo pipeline

Visão geral do fluxo híbrido

entry point: python -m hybrid_stereo_method.hybrid.main --param_file configs/hb_experiment.yaml
Dataset de entrada N_luzes × N_focos imagens sVal.png (uint16) + lights.npy + GT em sharp/
Etapa 1 — Estéreo Multifocal executada 1 + N_luzes vezes: na pilha média ("average") e em cada pilha por luz (L000…L012).
indicador de foco → argmax fuzzy → mosaico
sMos.npy (all-in-focus por luz)  ·  zMos_with_confidence.fni (average)
Etapa 2 — Estéreo Fotométrico solver robusto por mínimos quadrados com rejeição de sombras e outliers
(usa os sMos.npy por luz — a mesma cena, agora toda em foco, sob 13 iluminações)
normal_map.npy + confidence_map.npy
Etapa 3 — Integração de superfície solver multigrid recursivo em C (gus_integrate_recursive)
normais (+confiança como peso) → altura; zMos da average entra como hints
height_map.npy / height_map.png
Etapa 4 — Avaliação automática (opcional) compara cada artefato com o ground truth de sharp/ → metrics.json + report.md + mapas de erro
Ideia central do híbrido: o multifocal fornece a forma global (baixa frequência, mas com boa âncora absoluta de profundidade) enquanto o fotométrico fornece o detalhe local (alta frequência das normais, mas com deriva global). A integração combina os dois: as normais dominam o detalhe e o hints_weight controla o quanto a profundidade multifocal ancora a solução. A métrica hybrid_gain da Etapa 4 mede exatamente se essa combinação superou o multifocal sozinho.

experiment.paths.input / experiment.paths.data_folder

ETAPA 1

Estéreo Multifocal

profundidade e imagem all-in-focus a partir da pilha de focos · multifocus/main.py

Ramo A — pilha média ("average")

Para cada frame focal zf*, tira a média das N_luzes imagens (preservando uint16, normalize=False) e roda o multifocal nessa pilha. É dela que saem o zMos_with_confidence.fni usado como hints na Etapa 3 e a melhor estimativa de profundidade multifocal.

Ramo B — uma pilha por luz (L000…L012)

Roda o multifocal separadamente na pilha de cada luz. O produto que importa aqui é o sMos.npy (all-in-focus daquela luz, radiometria original), que vira a entrada da Etapa 2. O mosaico da average é excluído da lista fotométrica.

Sub-pipeline (idêntico nos dois ramos)

1 · Grayscaleconverte a pilha para tons de cinza
→
2 · Indicador de foco1 mapa por frame, método escolhido em focus_measure.method; depois clip ≥ 0 e normalização global da pilha para [0, 1]
→
3 · Argmax fuzzypor pixel: parábola ajustada em torno do pico da curva focal → índice sub-frame iSel + confiança wSel
→
4 · Mosaicointerpola z_foc e as intensidades no índice fuzzy → zMos (profundidade física) e sMos (all-in-focus)

2a · Métodos de indicador de foco (focus_measure.method)

métodocomo funcionaparâmetros próprios
fourierFFT 2D → máscara gaussiana elíptica passa-altas centrada no espectro → IFFT → |·|. Mede energia de alta frequência.parameters.radius — raio da máscara como fração das dimensões. Menor = corta menos baixas frequências (passa-altas mais agressivo perto do centro); 0.05 (low-freq) foi o melhor no sweep de 2026-07-10.
laplaciancv2.Laplacian (2ª derivada) → |·|. Sensível a bordas/textura.parameters.kernel_size — tamanho do kernel (ímpar obrigatório).
waveletDWT 2D (pywt.wavedec2) → magnitude √(cH²+cV²+cD²) do nível mais fino → resize de volta ao grid da imagem.wavelet haar e level=2 fixos no código (sem chave no YAML).

2b · Pré-processamento do indicador (aplicado nesta ordem)

parâmetrodefaultefeito
preprocessing.squareFalseEleva o indicador ao quadrado (amplifica diferenças de foco).
preprocessing.smoothFalseConvolui com kernel binomial 3×3 (/16) — suaviza ruído do indicador.
preprocessing.zero_borderTrueZera uma moldura fixa de 40 px do indicador (não da imagem) para eliminar artefatos de borda da FFT/convolução.
preprocessing.spatial_median_filterFalsecv2.medianBlur 5×5 no indicador — o "denoise" que melhorou o resultado no sweep.

3 · Argmax fuzzy (argmax_fuzzy.py, bloco multifocus.optimization)

  • Acha k_max = frame com maior soma de 3 focos consecutivos; ajusta uma parábola y = Ax² + Bx + C (np.polyfit ponderado — pesos proporcionais ao valor de foco) na janela k_max ± r.
  • r_max (default 2) — raio da janela de regressão, encolhido nas bordas da pilha.
  • polyfit_epsilon (default 1e-9) — se a parábola é convexa (A > 0) ou |A| < ε, o pixel é marcado como degenerado: iSel = n/2 (frame central) e confiança 0.
  • Caso normal: iSel = −B/2A (vértice, limitado a [0, n−1]) e confiança wSel = |A| / f(iSel) — picos agudos e altos ⇒ mais confiança. wSel é normalizado para [0, 1] no final.

4 · Mosaico (mosaic.py)

parâmetroopçõesefeito
parameters.interpolationlinear_interpolation · quadratic_interpolation · crop crop pega o frame inteiro mais próximo; as interpolações avaliam z_foc e as intensidades no índice fracionário iSel (sub-frame). Fora do intervalo, usa o frame extremo.
parameters.z_foclista de N floats Distância focal física de cada frame, na mesma ordem (natsort) das pastas zf*. Validação: se o tamanho difere do nº de imagens, o pipeline aborta com erro.

Saídas por execução (average e cada L*)

iSel.png/.fni índice fuzzy · wSel.png/.fni confiança · sMos.png visualização (normalizada!) · sMos.npy all-in-focus sem normalizar (consumido pela Etapa 2) · zMos.png · zMos.fni profundidade em unidades físicas · zMos_with_confidence.fni (z + wSel — vira hints da Etapa 3) · focus_indicator/*.png · debug_data/debug.csv (se debug)

Bloco declarado mas inativo: multifocus.depth_refinement (enabled, gaussian_size, unary_scale, pair_scale, n_iter) — o módulo depth_refinement.py (regularização por graph cut) existe, mas nenhum entry point o invoca. O mesmo vale para image_alignment.py (alinhamento ECC da pilha).
ETAPA 2

Estéreo Fotométrico

normais de superfície a partir da variação de iluminação · photometric/main_wps.py + wps.py
Entradas13 × sMos.npy (um all-in-focus por luz, radiometria original, → grayscale) + lights.npy (L: N×3)
estimate_normals_argmax_lstsq_robustresolve I = albedo·(L·n) por pixel, com rejeição de sombras e de outliers
Saídasnormal_map.npy · confidence_map.npy · normal_map_with_residuals.fni · selected_areas/*.png · visualizações (normal_map.png, channels, 3D)

Algoritmo robusto, por pixel

1 · Rejeita sombrasdescarta luzes com I/I_max ≤ shadow_threshold
→
2 · Checa dados< 3 luzes válidas ⇒ normal = NaN, confiança 0
→
3 · Mínimos quadradoslstsq: I = L·g
→
4 · Remove outliersdescarta equações com resíduo > outlier_threshold_multiplier × resíduo médio; repete 3–4 até estabilizar
→
5 · Resultadoalbedo = |g|, normal = g/|g|, confiança = (N/M) · 1/(1+σ_resíduos)

Parâmetros do solver (bloco photometric.solver)

parâmetrodefaultefeito
epsilon1e-6Somado a todas as intensidades para evitar divisão por zero.
shadow_threshold1e-3Razão mínima I/I_max para a luz contar como não sombreada. Maior = mais agressivo contra sombras (e menos equações por pixel).
outlier_threshold_multiplier3Multiplicador do resíduo médio para descartar equações (destaques especulares, inter-reflexões).
top_k3no-op no fluxo híbrido só é lido pelo solver simples estimate_normals_argmax, que não é chamado — confirmado no sweep de 2026-07-10.
Métodos alternativos: photometric.parameters.method aceita wodham_implementation_argmax no fluxo híbrido (main_wps.py); qualquer outro valor gera warning e cai no solver robusto. Os solvers L2 / L1 / SBL / RPCA existem, mas apenas no entry point standalone photometric/main.py (classe RPS), que também é o único que consome parameters.data_scale e parameters.image_extension (e um mask.png/gt_normal.npy do dataset).
Radiometria importa: a Etapa 2 lê os sMos.npy — os sMos.png são min-max normalizados por imagem, o que destruiria as razões de intensidade entre luzes exigidas pelo modelo I = L·n (correção do commit 16e0d19/09afd35).
ETAPA 3

Integração de Superfície

normais → mapa de altura · hybrid/integrate.py + binário C csrc/integrate_recursive/gus_integrate_recursive
normal_map.npy (H×W×3)+ confidence_map.npy anexado como 4º canal ⇒ peso por pixel de cada equação no sistema
Conversão para FNIheight_normals.fni — as normais viram gradientes dZ/dX, dZ/dY escalados por slopes_scale
gus_integrate_recursive (C, multigrid) resolve o sistema de Poisson ponderado recursivamente em níveis de resolução;
opcionalmente ancorado no zMos_with_confidence.fni da average via -hints
height-00-end-Z.fni → height_map.npy / height_map.pnggrade de vértices (H+1 × W+1)

Parâmetros (bloco hybrid.integration)

parâmetrodefaultefeito
initial_method"zero"Chute inicial do solver: zero, hints (parte do mapa de dicas) ou reference.
initial_noise0.0Perturbação aleatória adicionada ao chute inicial (0 = nenhuma).
use_hintsTrueSe True, procura multifocus_stereo/average/zMos_with_confidence.fni e o passa ao C via -hints. É aqui que o multifocal ancora o fotométrico.
hints_weight0.1Peso (0–1) das equações de dica vs. as equações de gradiente das normais. Alto = altura segue o zMos; baixo = segue as normais.
max_level30Profundidade máxima da recursão multigrid (níveis de meia resolução).
max_iter1000 (YAML) / 100000 (código)Iterações máximas do solver por nível.
conv_tol5e-7Tolerância de convergência por nível.
slopes_scale[1.0, -1.0]Escala [sx, sy] aplicada a dZ/dX e dZ/dY. sy = −1 corrige a convenção Y-up dos datasets Stolfi (melon24) vs. a ordem top-down do FNI.
Flags do código sem chave no YAML: sort_sys (ordena equações por peso) e report_step (dump de depuração por iteração) existem no IntegrateRecursiveConfig, mas hoje só são acessíveis programaticamente; verbose herda de experiment.settings.debug. Há também integrate_slopes_to_height() para integrar gradientes diretos (não usado no fluxo).

Como executar cada modo

# Pipeline híbrido completo (Etapas 1→4)
python -m hybrid_stereo_method.hybrid.main --param_file configs/hb_experiment.yaml

# Etapas isoladas
python -m hybrid_stereo_method.multifocus.main      --param_file configs/ms_experiment.yaml
python -m hybrid_stereo_method.photometric.main_wps --param_file configs/wps_experiment.yaml  # solver robusto
python -m hybrid_stereo_method.photometric.main     --param_file configs/ps_experiment.yaml   # RPS: L2/L1/SBL/RPCA

# Avaliação standalone de um resultado já gerado
python -m hybrid_stereo_method.evaluation.main --results_dir data/results/hybrid_stereo/<pasta> \
       [--data_dir <dataset>] [--hdev_mask] [--hdev_threshold 0.1]

# Sweep de parâmetros (15 configs prontas + geração + comparação)
python configs/sweep/generate_configs.py   # gera os YAMLs numerados 01–15
python configs/sweep/summarize.py          # tabela comparativa dos resultados

# Binário C da integração (pré-requisito da Etapa 3)
cd csrc/integrate_recursive && make

Observações que valem dinheiro

  • Config resolvido é salvo em parameters.yaml dentro da pasta de resultado — a avaliação standalone o usa para redescobrir o data_dir sozinha.
  • Melhor configuração conhecida para melon24 (sweep 2026-07-10): fourier com radius: 0.05 + spatial_median_filter: true + zero_border: false.
  • Nunca troque os .npy pelos .png nos consumidores intermediários: os PNGs são normalizados por imagem, só para visualização.
  • sy = −1 em slopes_scale é obrigatório para datasets com convenção Y-up (geradores Stolfi, ex. melon24).
