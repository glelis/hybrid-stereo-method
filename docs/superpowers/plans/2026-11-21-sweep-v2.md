# Sweep v2: busca de parâmetros multi-dataset — plano de implementação e execução

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Refazer do zero a busca de parâmetros do método híbrido sobre o código corrigido (pós-auditoria, calibração sy/pixel_size, faixa de escala excluída) em 4 bases com GT. A busca é em estágios, com seleção em bases de desenvolvimento e validação em bases separadas. A entrega é uma configuração recomendada robusta e, onde fizer diferença, uma por dataset.

**Architecture:** São três partes. (1) **Infra**: métrica principal medida no objeto (máscara de frente do GT, só na avaliação), dois knobs novos de denoise e reexecução parcial do pipeline a partir de um run existente, porque o multifocus custa cerca de 3 min por run e não precisa ser refeito quando só mudam fotométrico ou integração. (2) **Framework `configs/sweep_v2/`**: registro de datasets, gerador por estágio (grade/OFAT em torno de um "centro"), runner paralelo idempotente com poda de disco e sumário com ranking, regra de empate e promoção do vencedor a centro do estágio seguinte. (3) **Execução**: estágios S0 → A1 → A2 → B → C → V → relatório.

**Tech Stack:** Python 3 (numpy, opencv, PyYAML, pytest), integrador C `gus_integrate_recursive`, bash.

**Spec:** este documento (pedido do usuário em 2026-11-21). Contexto prévio: `docs/relatorios/relatorio_sweep_parametros.md` (sweep 2026-07-10) e `docs/relatorios/2026-11-21-fundo-vs-normais.md`.

## Métricas e regra de decisão

- **Primária:** `integration_height_object.pearson_r`, a altura final contra o `hAvg` dentro da máscara de frente do GT, sem a faixa de escala. Desempate: `integration_height_object.rmse_affine`.
- **Secundárias, reportadas e não usadas para escolher:** `multifocus_depth_object.pearson_r`, `focus_selection.median_err_frames`, erro angular das normais, `integration_height.pearson_r` (imagem toda), `hybrid_gain_object.gain`.
- **Empate:** duas configs empatam se |Δr| < 0,005 **e** Δrmse relativo < 2 %. No empate vence a mais simples: menos desvios do centro, preferindo o default atual.
- **Escolha multi-dataset (estágio V):** maximizar a média de r entre os datasets, restrita a `min_r ≥ (melhor min_r) − 0,01`. Reportar também o vencedor de cada dataset.
- **Anti-overfitting:** A1, A2, B e C escolhem só com d1 e d2. d3 e d4 entram só no estágio V.

## Review Focus

1. **Pasta de dataset no layout plano** (`data/raw/datasets/hybrid/<nome>/L000/zf*/`) e não no aninhado `out/<cena>/<res>/`: o pipeline e a avaliação devem achar `lights.npy`, `zf*` e `sharp/` do mesmo jeito. Teste em S0 (Task 5).
2. **Pastas de luz com sufixo** (`L000-amb0.00-glo0.00`, do d3): `collect_light_dirs`, `select_per_light_smos` e `find_sharp_dir` precisam funcionar. Teste em S0 (Task 5); um teste unitário na Task 3 se o S0 falhar.
3. **Rerun com config incompatível**: um `--from_stage integration` cujo bloco `multifocus` difere do run de origem tem que **abortar** e mostrar a diferença, em vez de produzir métricas atribuídas à config errada. Teste na Task 3.
4. **Poda seguindo symlink**: podar um run de rerun não pode apagar arquivos do run de origem. Teste na Task 4.
5. **Run interrompido ou falho**: o runner reexecutado pula o que tem `metrics.json` e refaz o resto; um run sem `metrics.json` nunca entra no ranking como se tivesse r = 0. Teste na Task 4.

Para cada estágio: `run.py --stage X --datasets <ds> -j <J> --prune` → `summarize.py --stage X` → revisar o `.md` (outliers, runs falhos, se o vencedor faz sentido) → `summarize.py --stage X --promote` → commit dos centros e do relatório parcial em `docs/relatorios/sweep_v2/`. Os tempos estimados assumem cerca de 6 min por run completo, cerca de 3,5 min por rerun e `-j 3`; a Task 5 recalibra essas estimativas.

### Task 6: A1, grade da medida de foco (d1, d2; `mode=full`)

O denoise e o zero_border interagem com o método (essa foi a lição de 2026-07), então isto é uma grade fatorial e não OFAT.

```
fourier:   radius ∈ {0.02, 0.03, 0.04, 0.05, 0.07, 0.10}
laplacian: kernel_size ∈ {5, 9, 15, 21, 31}        (cv2: ímpar, ≤ 31)
× smooth ∈ {F, T} × spatial_median_filter ∈ {F, T} × zero_border ∈ {F, T}
+ wavelet com {smooth T, median T, zb F} (1 spec de sanidade)
```

= (6 + 5) × 8 + 1 = **89 specs por dataset, 178 no total** (cerca de 6 h). `square`, `r_max` e a interpolação ficam no centro.
- [ ] Executar, sumarizar e promover. Critério extra de revisão: se o vencedor estiver na **borda da grade** (radius 0,02 ou 0,10, kernel 5 ou 31), acrescentar um ponto além da borda e rodar de novo antes de promover.
- [ ] Registrar no relatório: o efeito principal de cada fator, como média de r sobre os outros fatores, e as interações fortes.

### Task 7: A2, refino do multifocus (d1, d2; `mode=full`)

OFAT em torno dos **top-3 distintos** de A1 em cada dataset. São 3 centros, e o estágio aceita `centers` múltiplos via `centers/<ds>.top3.yaml`, gravado por `summarize --promote --top 3`.

```
r_max ∈ {1, 3, 4}
interpolation ∈ {quadratic_interpolation}
median_ksize ∈ {3}                         (só nos centros com median T)
smooth_sigma ∈ {0.75, 1.5, 2.5}            (só nos centros com smooth T)
square ∈ {T}
```

Até 9 specs × 3 centros = **≤ 27 por dataset** (cerca de 2 h no total).
- [ ] Executar, sumarizar e promover um único vencedor por dataset.

### Task 8: B, fotométrico (d1, d2; `mode=photometric`, rerun sobre o vencedor de A2)

```
shadow_threshold ∈ {1e-4, 1e-3, 1e-2, 5e-2}
× outlier_threshold_multiplier ∈ {2, 2.5, 3, 4, 1e9}   (1e9 = sem rejeição de outliers)
```

= **20 por dataset** (cerca de 40 min). Expectativa registrada antes de rodar: em d1 o efeito é nulo, porque as normais já estão quase iguais às do GT (relatório fundo-vs-normais). Em d2, com brilho, a rejeição de outliers deve importar. Se d1 confirmar o efeito nulo, isso é um achado, não uma falha.
- [ ] Executar, sumarizar (incluir o erro angular médio e o p95 das normais na tabela) e promover.

### Task 9: C, integração (d1, d2; `mode=integration`, rerun sobre o vencedor de B)

```
C1: hints_weight ∈ {0, 0.01, 0.03, 0.05, 0.1, 0.2, 0.3} × initial_method ∈ {zero, hints}   (14; hints_weight 0 ⇒ use_hints false)
C2: pixel_size × {0.8, 0.9, 1.1, 1.25} sobre o calibrado, no melhor de C1                    (4; teste de sensibilidade, NÃO de seleção)
C3: interação: top-3 de A1 (rerun de integração sobre os runs deles) × {hints_weight vencedor, 0.1}   (≤ 6)
```

São ≤ 24 por dataset (cerca de 1 h 30). C2 só é reportado: se um `pixel_size` fora do calibrado ganhar com folga (> 0,01), é sinal de erro de calibração, e isso **vai para o usuário**, sem promover. Se C3 mostrar que outro top-3 de A1 passa à frente com o novo `hints_weight`, promover esse.
- [ ] Executar, sumarizar e promover.
